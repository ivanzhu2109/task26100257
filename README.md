# fuzzyjoin

双来源模糊联接库（Go，纯进程内存，无外部依赖）。对两份已清洗、已完成字段映射的
客户名册做对齐：按 Levenshtein 相似度完整找出全部跨来源候选记录对，供上层融合
任务与人工确认使用。本模块不负责合成主记录。

## 规则

- 输入为两个静态来源，每条记录只有来源内唯一标识 `ID` 与匹配键 `Key`
  （1 至 64 个 Unicode 码点，不做大小写转换、去空白或 Unicode 规范化）。
  相同键可对应多条记录，记录身份在结果中完整保留（m×n 展开）。
- 编辑距离为码点级 Levenshtein（插入、删除、替换代价均为 1，相邻交换不算一次编辑）。
- 相似度 = 1 − 距离/较长键码点数；固定返回相似度 ≥ 0.85 的全部跨来源记录对。
  边界按精确数学值判断（整数比较 `20·d ≤ 3·L`），与四舍五入无关。
- 每对恰好出现一次，附精确编辑距离；不返回同源配对，不做传递合并，
  不限制每条记录的匹配数量。
- 结果顺序不限，逐条流式消费，调用方可随时提前结束本次联接。

## 使用

```go
import "fuzzyjoin"

left := []fuzzyjoin.Record{{ID: "L1", Key: "客户名称甲"}, ...}
right := []fuzzyjoin.Record{{ID: "R1", Key: "客户名称乙"}, ...}

fuzzyjoin.Join(left, right, func(p fuzzyjoin.Pair) bool {
    // p.LeftID, p.RightID, p.Distance（精确编辑距离）
    consume(p)
    return true // 返回 false 立即结束本次联接，之后不再产生任何计算
})
```

`Join` 在 `yield` 返回 `false` 时立即停止并返回；即使潜在结果有 1 亿对，
提前结束也能在毫秒级返回（见性能测试）。

## 实现要点

- 相同键先聚合成组，组间只算一次距离，记录按组展开，保证 m×n 对不丢身份。
- 完全相同的跨来源键走哈希联接（距离 0），不进入候选过滤。
- 近似候选用 q-gram（q=3）计数必要条件过滤：距离 ≤ d 的两串至少共享
  `L−q+1−q·d` 个 q-gram；高频停用 gram（posting list 超过 512）不计入并相应
  下调阈值，保证只增候选、不漏候选。
- 候选用带状 Levenshtein（带宽 = 阈值允许的最大距离）精确确认，
  长度差超过阈值的对在 O(1) 时间排除。

## 性能（Apple Silicon 实测，`go test -run TestPerf`）

- 标准批次：每源 5 万条、键长 28–36 码点、80% 共享 8 码点前缀、5000 条
  1–4 次编辑变体 —— 约 1.9 秒完成（含预处理），峰值堆内存约 57 MiB，
  产出 5000 对（上限分别为 30 秒 / 256 MiB / 10 万对）。
- 两侧各 1 万条相同键（潜在 1 亿对）：消费前 1000 对后结束，约 1 毫秒返回。

## 测试

```sh
go test ./...        # 全部：正确性（对照逐对暴力）+ 性能 + 提前结束
go test -short ./... # 跳过 5 万对级性能批次
```

正确性测试以逐对完整计算编辑距离的暴力实现为参照，覆盖不同长度、中文、
补充平面字符（如 emoji）、重复键、多候选、长度 20 距离 3 匹配 / 距离 4 排除、
插入删除形成的匹配，以及多组随机小批次的完全一致比对。
